# Economy Module

## 目的

Economy Moduleは、協力基盤における価値交換、ポイント、生活アクセス、経済圏を扱います。

目的は、法定通貨を否定することではなく、人が生活のあらゆる場面で通貨不安に縛られ続ける状態を減らすことです。

## このモジュールが解決する問題

現在の経済は国家通貨に強く依存し、人々が常に法定通貨を意識せざるを得ない構造になっています。

この設計では、法制度を尊重しつつ、生活上の通貨意識を減らす経済設計を目指します。

## 責任範囲

- 内部ポイント
- 生活アクセス
- 共同購入
- 経済圏
- 価値交換
- 貢献と利用の接続
- 税務・法務との接続方針

## 責任範囲外

- 違法な通貨発行
- 税回避
- 強制的な給与代替
- 参加者の経済活動の一元管理

## 他モジュールとの関係

Economyは、Identityによる利用者や組織の識別、Welfareによる生活支援、Governanceによるルール変更、Arbitrationによる紛争解決と接続します。

Reputationに相当する信用設計とも関係しますが、信用評価が経済アクセスを過度に支配しないように注意します。

## 初期設計メモ

内部ポイントや生活アクセスは、法定通貨、税務、労務、資金決済規制との境界を慎重に整理する必要があります。

初期段階では、実際の通貨実装ではなく、概念、リスク、法務確認ポイント、運用仮説を文書化します。

この文書は法務判断ではありません。実際にポイント、交換、報酬、決済、換金、資産移転を扱う場合は、対象地域ごとの専門家レビューを必須とします。

## 法定通貨と内部ポイントの関係

Economy設計では、少なくとも次の4つを分けて扱います。

### 1. 法定通貨

法定通貨は、既存の法制度、税務、会計、労務、契約、決済と結びついた通貨です。

この設計は法定通貨を否定しません。初期段階では、外部サービスの購入、寄付、経費、給与、税務、会計処理などは、原則として既存の法制度に従って扱います。

### 2. 内部ポイント

内部ポイントは、協力基盤内の貢献、利用、配分、優先度、実験的な経済設計を記録するための単位です。

内部ポイントを設計する場合は、次の点を明確にします。

- 何を記録するポイントなのか
- 誰が発行・変更・失効できるのか
- 参加者間で移転できるのか
- 法定通貨へ換金できるのか
- 商品やサービスの支払いに使えるのか
- 有効期限や取消条件があるのか
- 会計・税務・労務上の扱いを誰が確認するのか

内部ポイントは、名前だけを変えれば法的論点を避けられるものではありません。実態として価値交換、前払い、報酬、換金、投資、決済に近づくほど、確認すべき論点は増えます。

### 3. 生活アクセス

生活アクセスは、食、住、通信、教育、健康支援など、生活に必要な基盤へ接続できる状態を指します。

生活アクセスは、必ずしもポイント残高と一対一で結びつける必要はありません。共同購入、寄付、相互扶助、利用枠、会員制、地域ごとの運用など、複数の設計があり得ます。

重要なのは、生活アクセスが参加者を囲い込む手段にならないことです。支援を受けた人が離脱できなくなる、思想や労働を強要される、異議申し立てができない、といった構造は避けます。

### 4. 貢献記録

貢献記録は、参加者が行った作業、支援、翻訳、調査、レビュー、運営補助などを記録するものです。

貢献記録は、信用、感謝、役割付与、優先利用、報酬検討などに使われる可能性があります。ただし、貢献記録がそのまま身分差、恒久的な特権、生活アクセスの過度な制限にならないようにします。

## 初期設計原則

- 法定通貨、内部ポイント、生活アクセス、貢献記録を混同しない
- 内部ポイントを実装する前に、用途、移転性、換金性、失効、管理権限を文書化する
- 「通貨ではない」と書くだけでなく、実態として何に使えるかを確認する
- 税務、会計、労務、資金決済、消費者保護、寄付、景品、会員権などの論点を早めに洗い出す
- 生活アクセスを、離脱不能性や服従要求につなげない
- 経済設計の変更はProposalで扱い、重要な判断はDecisionへ残す
- 小さく実験し、失敗や悪用ケースを記録する

## 法務・運用レビューが必要な例

以下に近い設計は、実装前に必ず専門家レビューを行います。

- 事前に金銭を受け取り、後で商品やサービスに使える残高を発行する
- ポイントを参加者間で譲渡できる
- ポイントを法定通貨や暗号資産に交換できる
- ポイントの価格が外部資産や通貨と連動する
- 労働や業務委託の対価としてポイントを渡す
- 出資、配当、利回り、投資性のある説明を行う
- 国や地域をまたいで利用者、発行者、提供者が分かれる
- 生活支援の条件が雇用、所属、役割、罰則と結びつく

## 初期実験の候補

初期は、法的・運用的な不確実性が比較的低い領域から始めます。

- 貢献記録の整理
- 共同購入のルール文書化
- 寄付や経費の透明な記録
- 生活支援ニーズの匿名集計
- ポイントを発行しない相互扶助の運用実験
- ポイント案を実装せず、Proposalとしてリスクレビューする

## 未解決の問い

- 法定通貨と内部ポイントの境界
- 税務・労務との整合性
- 換金性をどう制御するか
- 経済的依存や囲い込みをどう防ぐか
- 生活アクセスを公平かつ離脱可能にする条件
- 貢献記録を評価や報酬へ接続する場合の透明性
- 国や地域ごとの法制度差をどう扱うか
