# アイデンティティモジュール

## 目的

アイデンティティモジュールは、個人や組織のアイデンティティ、本人性、所属、権限を扱います。[アーキテクチャ](../../../docs/ja/02-architecture.md) 上では、[評判](../reputation/README.md)、[ガバナンス](../governance/README.md)、[連合](../federation/README.md) と接続します。

ここでいうアイデンティティは、階層的な身分制度ではありません。誰が、どの組織に、どの権限で参加しているかを、透明かつ離脱可能な形で扱うための基盤です。

## このモジュールが解決する問題

現在の本人確認や所属証明は、国家、企業、学校、プラットフォームに強く依存しています。

この設計では、国境や単一組織に縛られず、多重所属可能なアイデンティティ基盤を目指します。

## 責任範囲

- 個人ID
- 組織ID
- 所属
- 権限
- 認証
- 多重所属
- 本人性と匿名性の扱い

## 責任範囲外

- 信用評価
- 経済取引
- 紛争解決
- 思想や人格の統制

## 他モジュールとの関係

アイデンティティは、[ガバナンス](../governance/README.md) の投票権や役割、[経済](../economy/README.md) の利用権、[福祉](../welfare/README.md) の支援対象、[仲裁](../arbitration/README.md) の当事者確認と接続します。

ただし、アイデンティティが信用、経済、仲裁の判断を直接支配しないように分離します。

## 初期設計メモ

国家IDや企業アカウントとの接続は必要になる可能性がありますが、この設計におけるアイデンティティをそれらへ完全従属させない設計が必要です。

本人性、匿名性、仮名性、組織所属を分けて扱うことで、安全性と自由度の両立を検討します。
