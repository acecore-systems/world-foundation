# 連合モジュール

## 目的

連合モジュールは、複数の自律組織が共通プロトコルで協力するための連盟設計を扱います。[アーキテクチャ](../../../docs/ja/02-architecture.md) と [ロードマップ](../../../docs/ja/03-roadmap.md) では、単一支配ではなく相互接続のための層として扱います。

連盟は中央政府や単一支配組織ではありません。各組織の自治、離脱可能性、フォーク可能性、多重所属を保ちながら相互接続するための仕組みです。

## このモジュールが解決する問題

単一組織だけでは、地域差、文化差、法制度差、専門領域の違いに対応しきれません。

一方で、各組織が完全に分断されると、信用、生活支援、仲裁、監査、翻訳、相互協力が難しくなります。

このモジュールは、独立性と相互運用性を両立するための組織連盟プロトコルを設計します。

## 責任範囲

- 組織間参加
- 多重所属
- 組織間の相互承認
- 組織ごとの自治
- 共通プロトコル準拠
- フォーク時の互換性
- 評判の組織間共有方針
- 監査の組織間検証方針
- 仲裁の組織間接続
- 連合からの離脱
- 連盟標準と地域差の両立

## 責任範囲外

- 単一世界政府
- 中央支配組織
- 組織自治の否定
- 連盟からの離脱妨害
- すべての組織への同一運用強制
- 地域法制度の無視
- 連盟標準を使った囲い込み

## 他モジュールとの関係

- [監査](../audit/README.md): 組織間検証と透明性を扱う

## 初期設計メモ

初期は、連盟の制度を完成させるよりも、連盟が支配機構に見えないための安全境界を明確にします。

共通プロトコルは、各組織の自治を置き換えるものではなく、相互接続のための最小限の合意として設計します。

## 未解決の問い

- 連盟参加条件をどこまで共通化するか
- 組織間評判をどう共有するか
- 連盟から離脱した組織のデータや信用をどう扱うか
- 連盟標準の変更手続きをどう設計するか
- 連盟の乗っ取りをどう防ぐか
